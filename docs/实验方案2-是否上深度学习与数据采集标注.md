# 实验方案 2：是否上深度学习，以及数据采集与标注

本文回答两件事：光学参数已经由方案 1 锁定之后，**要不要上深度学习**；如果要上，数据怎么采、`abnormal_flame` 怎么标、怎样接到 ESPDet-Pico / esp-detection。全文是文档约定，本仓库不提供训练脚本、固件或权重。

先完成 [实验方案 1](实验方案1-光学信噪比标定.md) 的验收，并阅读 [安全须知](安全须知.md)。

## 1. 何时不上深度学习

默认路径是 **UV 硬触发 + 阈值（再加简单时序）**。下面几条都成立时，不上检测模型：

1. 方案 1 已通过：选定工作点上异常 SNR 中位数 ≥ 5，正常切割伪阳率 < 1%，过曝帧 < 2%。跨材料若尚未通过，模型也先不上，先回到滤光。
2. 在试点片段上，下面的规则能分开「正常火花 / 熔渣」和要抓的异常，且误报代价产线能接受：
   - UV（185–260 nm 一类太阳盲管）在毫秒级给出「有碳氢火焰」的硬触发，并直接拉低激光使能；
   - 视觉只提供标量：信号 ROI 的面积或超阈值像素数、持续了多久、质心是否离开切缝。
3. 停光决策以 UV / 机床联锁为准。视觉阈值只做确认、定位和压制误报。

正常切割本来就有火、有火花、有等离子体。规则的任务是判断光信号是否偏离「这种材料、这组参数、这一加工阶段」应有的样子，而不是判断画面里有没有亮斑。

公开火灾、野火、室内火焰数据集与滤光后的准单色画面不一致，不能当作「先训一个火灾模型试试」的理由。数据集说明见第 3 节。

## 2. 何时才上

同时满足下面三条，才进入采集、标注和 ESPDet-Pico：

1. 方案 1 的工作点已锁定，采集全程使用该滤光、曝光、增益、分辨率和位姿。模型要学的是异常形态，不是某一档曝光。
2. 试点上，面积、持续时间、相对切缝位置和 UV 已经加上，硬负样本仍让伪阳超过产线限度。典型硬负样本：邻机焊光、日光灯频闪、阳光、金属反光、红色材料、镜头污渍、停光后的余烬、穿孔与拐角减速。
3. 需要知道异常在画面的**哪里**（框或区域），标量阈值给不出可用位置。

上了模型之后，职责不变：UV 仍是毫秒级停光；ESPDet-Pico 是中环，做定位、趋势和误报压制。标准 YOLO 在 ESP32-P4 上大约 1 fps 量级，只适合抽帧核对，不作为停光主依据。该量级摘自选型 canvas 所引公开讨论，**本库未复测**，以 [esp-dl issue #213](https://github.com/espressif/esp-dl/issues/213) 与 [espressif/yolo26](https://github.com/espressif/yolo26) 当前说明为准。

## 3. 自采规格

部署和评测只用自采数据。公开数据的用途写在表后。

| 维度 | 规格 |
| --- | --- |
| 光学与相机 | 锁死方案 1 的滤光、曝光、增益、ROI、分辨率、帧率；AE、AWB、自动增益保持关闭 |
| 像素格式 | 与方案 1 相同的码值路径。彩色模组沿用方案 1 选定的通道，或在 ISP 输出里固定同一格式，并写入采集说明 |
| 两套帧率 | 挖掘特征时可以高帧率。进训练集的那一套按 ESP32-P4 实际能跑的约 5–20 fps 重采（224 输入高于此上限、416 接近下限；具体以板上实测为准，待核实） |
| 材料 | 覆盖真实要加工的材料。建议至少含一种非金属（亚克力或木板）和一种金属（铝或钢），金属段须满足安全须知 |
| 工艺参数 | 功率 × 速度 × 气压（或该机床的等价参数）。每种材料含常用点、偏安全一侧、临界一侧 |
| 加工阶段 | 穿孔、稳定切割、拐角减速、收刀、停光后余烬窗口。穿孔单独打阶段标签，规则与训练都可以按阶段屏蔽 |
| 正常段 | ≥ 60–100 段完整加工。一段 = 一次连续起停，而不是随机抽帧 |
| 异常段 | ≥ 150 段，其中阴燃 ≥ 30 段。受控引燃 / 阴燃 / 回火模拟，全程值守 |
| 负样本比例 | 负样本帧数 : 正样本帧数 ≈ 5 : 1 到 10 : 1 |
| 划分 | 按任务、批次、材料切分训练/验证/测试。禁止把同一段视频的帧随机拆进训练和测试 |

单段建议记录：日期、机床、材料、功率、速度、气压、阶段、滤光与曝光增益（应与方案 1 获胜点一致）、是否异常、异常类型、onset 时刻（异常段）、文件名。

### 3.1 公开数据能做什么

滤光之后画面是准单色灰度，橙红火焰的颜色特征不存在；画面里有熔渣、切缝和喷嘴，公开火灾图里没有。任务也不同：要判的是**异常**，不是「有火」。

| 公开数据 | 本场景中的用途 |
| --- | --- |
| D-Fire、FASDD、PyroNear、MS-FSDB、DFS | 只作负样本或骨干预热。不当评测集，不把其权重直接烧录部署 |
| MVTec AD | 异常检测的方法参照 |
| 同轴切割公开视频（如 KU Leuven、米兰理工相关工作） | 光路和特征的定性参考 |

跨域掉点有公开实证。PyroNear 的预印本在 [arXiv:2402.05349](https://arxiv.org/abs/2402.05349)；同源与跨集的具体指标**以原文为准**，本库不转写未逐项核对的分数。上述数据集的精确规模标「待核实」，不以二手表格里的「约数」作为验收依据。

## 4. 三类样本怎么区分

| 类别 | 里面有什么 | 标注 |
| --- | --- | --- |
| 正常 | 稳定切缝、白炽缝、等离子体羽流、熔渣飞溅、单颗短时火花、稀薄被抽走的烟、穿孔阶段的正常光斑 | **不标** `abnormal_flame` |
| 异常 | 偏离该材料×参数×阶段的持续燃烧：面积单调变大、离开切缝、停光后仍存活的明火；受控阴燃；受控回火（若光路看得见） | 标 `abnormal_flame`。持续烟柱若单独要检，标 `smoke`，不要并进火焰类 |
| 硬负样本 | 日光灯频闪、阳光、邻机焊光、镜面/拉丝反光、红色或高反材料、镜头油污与保护窗结雾、抽烟、正常火花密集区、余烬巡检窗口里的正常暗热 | 默认不画火框。整段记入硬负样本清单，训练时作为背景。现场新干扰补进清单 |

正常火花寿命短、贴着切缝、没有持续增长。把它们标成火，模型会把正常加工学成报警。

## 5. 标注规范

### 5.1 类别名

`classes.txt` 顺序固定，一行一个名字：

```text
abnormal_flame
smoke
```

只做火焰异常时，文件里只留第一行，`abnormal_flame` 的类别 id 为 0。增加 `smoke` 时它是 id 1，**禁止**把已发出的 id 对调。

业务名使用 `abnormal_flame`。选型 canvas 里举例过 `anomaly_flame`，本仓库以 `abnormal_flame` 为准，避免两套名字并存。

### 5.2 什么时候画框

- 画可见的异常燃烧区域，框紧外焰，不框整幅图，不框喷嘴和整条切缝。
- 被烟或夹具挡住的部分只框可见区域。
- 出画的目标框到图像边缘。
- 同一帧多处异常，一处一框。
- 拿不准的帧不要猜成正类：帧号记入 `uncertain.csv`（列：`file,frame,question`），由第二人复核后再决定是否补框。
- 正常火花、熔渣、等离子体、白炽切缝、烧焦边缘：不画框，不标成 `abnormal_flame`。
- 烟只在确实要检烟时标 `smoke`。稀薄、随抽风立刻散掉的烟不标。

异常段另外在段清单里记录 onset：观察者认为「从这一时刻起属于异常」的时间戳或帧号。框可以晚于 onset（火焰变大之后才够画），onset 仍按事件记，不按第一个框反推。

### 5.3 工具与 YOLO 导出

可用 CVAT、LabelImg、X-AnyLabeling 或 Roboflow 等任何能导出 YOLO 检测 txt 的工具。本库不绑定其中之一。

导出为每张图一个同名 `.txt`，每行：

```text
<class_id> <x_center> <y_center> <width> <height>
```

四个坐标相对图像宽高归一化到 0–1。没有目标的图：对应 txt 为空文件，图仍然保留，作为负样本。不要删掉空标签图。

建议的数据目录（放在数据仓库或对象存储，**不要提交进本仓库**）：

```text
dataset/
  classes.txt
  images/<split>/<name>.jpg
  labels/<split>/<name>.txt
  segments.csv          # 段级：材料、参数、阶段、onset、划分
  hard_negatives.csv    # 硬负样本段清单
  uncertain.csv
```

`<split>` 只用 `train`、`val`、`test`，且与段级划分一致：同一 `segments.csv` 里的一段视频，其所有帧只进入一个 split。

图像文件名沿用方案 1 的可读性，并加上段号与帧号，避免覆盖：

```text
BP750+SP1000_1ms_0dB_亚克力_异常代理_s012_f000381.jpg
```

### 5.4 交叉一致率

每个批次至少抽 **10%** 的段，由第二名标注员独立重标，抽检段在标注开始前指定，不要挑「好看」的段。

框级匹配：类别相同且 IoU ≥ 0.5。

```text
一致率 = 2 × 匹配框数 / (标注员 A 的框数 + 标注员 B 的框数)
```

本库工作约定：一致率 **≥ 0.80** 该批次才可进入训练。低于 0.80 时，先改本页示例、回标该批次，再重新抽检。0.80 是本仓库的约定，不是外部标准。

事件级另查 onset：两人相差超过 0.5 秒则记一次事件不一致，写入批次备注。0.5 秒是否过宽，留待首轮标注后复核（待核实）。

## 6. 与 ESPDet-Pico / esp-detection 的衔接

训练与部署的操作步骤以乐鑫当前文档为准，本文只规定接缝，避免数据格式和类别名在两边漂掉。

| 环节 | 约定 |
| --- | --- |
| 训练项目 | [espressif/esp-detection](https://github.com/espressif/esp-detection/)。自定义类别训练 ESPDet-Pico，优先输入 **224×224**；召回不够再试 **416×416** |
| 类别 | 与 `classes.txt` 一致：`abnormal_flame`，可选 `smoke`。单类即可，不必做 COCO 八十类 |
| 公开权重 | 不把野火/室内火灾检测权重当作本场景检测器烧录 |
| 量化 | 导出后走 [ESP-DL](https://github.com/espressif/esp-dl) INT8。校准集必须含本机高亮饱和帧和硬负样本，避免校准被熔池亮点拉偏，暗部全部死掉 |
| 板上数据流（概念） | MIPI CSI → 片上 ISP → 裁切缝邻域 ROI / letterbox → ESP-DL 推理 → 连续 N 帧投票。N 的具体值待试点确定 |
| UV | GPIO 中断与视觉并行。中断优先级高于推理任务。视觉结果不能挡住 UV 停光 |
| 早火 | 异常区域往往只占全图很小一块。先裁 ROI 再推理 |
| 指标 | 不用 COCO mAP 作为通过条件。看：每百小时误报次数、从 onset 到停光的延迟 P50/P95、分级是否正确（提示 / 降速 / 停光） |

选型 canvas 引用 esp-detection 的公开测量：ESPDet-Pico 224×224 端到端约 51.4 ms（高于 18 FPS），416×416 约 201.7 ms（约 5 FPS）。**本库未复测**，以该仓库 README 的当前表格为准。

投票至少包含空间一致性：命中位置在相邻帧上要重叠（IoU 或质心距离）。只数「连续几帧有框」会把散落火花计成火。穿孔、拐角减速、密集回填由段清单里的阶段标签或机床信号屏蔽。

本仓库到此为止：不包含 ESP-IDF 工程、量化脚本和权重文件。固件与训练放在别的仓库，类别名和标签格式按本节执行。
